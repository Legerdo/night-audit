# 최초 요청 대비 변경 사항

최초 요청(「13층: 야간점검 / 13F: Night Audit」 제작 명세)과 실제 결과가 다른 부분만 정리했습니다. 명세대로 구현된 항목은 적지 않았습니다. 검증 수치와 날짜는 `docs/validation.md`를 기준으로 합니다.

## 1. 작업 환경과 도구

| 최초 요청 | 실제 |
| --- | --- |
| Codex CLI 안에서 동작하는 에이전트로 작업 | Kiro IDE 안에서 Claude Opus 5.5가 작업했습니다. Codex CLI(0.158.0)는 이미지 생성에만 썼습니다. |
| GPT Image 2.5급 모델을 확인한 뒤 사용하고, 필요하면 API 헬퍼 작성 | Codex 내장 `image_gen` 도구를 썼습니다(`tools/imagegen/codex-image.ps1`). 이 도구가 쓰는 실제 이미지 모델 이름은 로그에 나오지 않아 **확인하지 못했습니다**. `OPENAI_API_KEY`가 없어 API 직접 호출 헬퍼는 만들지 않았습니다. |
| 빠른 생성 경로와 고품질 편집 경로를 나눠 사용 | 경로가 하나뿐이었습니다. 일반 생성은 프롬프트만, 편집은 승인된 원본을 참조 이미지(`-RefImage`)로 넣어 같은 도구로 처리했습니다. |
| QA에 PIL/OpenCV/SSIM 등 사용 | PIL·OpenCV·NumPy로 SSIM, LabΔE, ROI 마스크를 직접 구현했습니다. scikit-image는 설치되어 있지 않아 쓰지 않았습니다. |

## 2. 이미지 파이프라인

- **확대 순서:** 명세는 "첫 배치를 게임에 통합해 렌더링 결과를 본 뒤 확대"였습니다.
  - 실제로는 첫 배치(가족사진 쌍, 입주민 초상 쌍, 광고 포스터, 준공식 사진 쌍)를 생성하고 QA를 한 뒤, **게임 루프가 완성되기 전에** 나머지 이미지 생성을 시작했습니다.
  - 인게임 확인은 모든 이미지가 준비된 뒤에 했습니다. 확인 과정에서 이 때문에 다시 만든 이미지는 없었습니다.
- **ROI 밖 합성(명세에 없던 추가 단계):** 편집본에서 의도한 영역 밖의 픽셀을 원본 픽셀로 되돌리는 합성을 넣었습니다(가족사진, 이순자 초상, 엘리베이터 광고 3쌍). 모델이 만든 미세한 흔들림이 우발적 단서가 되지 않게 하려는 조치입니다.
- **거절된 시도:** 엘리베이터 광고 편집 v1은 사람 형체가 너무 작아 폐기하고 v2를 썼습니다. 기록은 `art/pairs.json`에 있습니다.
- **포스터:** 실종자 전단과 안내문은 이미지 생성을 쓰지 않고 코드(Canvas)로 그렸습니다. 생성 이미지로 만든 포스터는 엘리베이터 분양 광고 1종입니다.

## 3. 게임 내용

- **이상현상 수:** 목표 범위(35–50) 안인 **50개**입니다. 레지스트리에는 원래 약 55개가 있었는데, QA 중 5개를 코드째 뺐습니다: `obj_light_warm`, `hum_cctv_player_absent`, `sys_door_plate_13`, `tmp_caption_future`, `tmp_cctv_lobby_daylight`. 항목별 제외 사유는 따로 기록하지 않았습니다.
- **3D 인물:** 얼굴 없는 단순 형태로 만들었습니다(명세에는 표현 방식에 대한 요구가 없었습니다). AI 얼굴이 흔들려서 생기는 오탐을 막기 위한 선택입니다.
- **오디오:** 오디오 파일을 쓰지 않고 WebAudio로 모든 소리를 합성했습니다.
- **폴더 구조:** 명세의 예시(`src/anomalies`, `src/systems/anomaly` 등)와 다릅니다.
  - 이상현상 정의는 `src/data/anomalies.ts`에 있습니다.
  - 런타임 동작은 `src/game/runtime.ts`에 있습니다.
  - 물리적 변형은 각 층 빌더(`src/world/*`)에 있습니다.

## 4. 디버그 도구 (명세 대비 일부만 구현)

- 구현한 것:
  - 이상현상 강제 적용(층 지정)
  - 위치 순간이동
  - 오염도 설정
  - 시드·현재 이상현상 표시
  - 스크린샷
  - 자동 진행
- 구현하지 않은 것:
  - 정상/이상 상태 **토글** 버튼, 현재 이상현상 **리셋** 버튼
  - **CCTV 이상현상 순환** 버튼
  - **신뢰 데이터 상태(신뢰 등급) 표시** 패널
- 강제 적용과 태블릿 화면으로 같은 확인은 할 수 있지만, 전용 버튼은 없습니다.

## 5. 테스트와 검증 방식

- **"한국어 현지화 키 해석" 테스트:** 문자열을 키로 관리하는 i18n 구조를 두지 않고 한국어를 코드에 직접 썼습니다. 그래서 대신 DOM 감사(`tests/e2e/ui-audit.mjs`)를 만들었습니다. 3개 해상도에서 영어 잔존, 잘린 글자, 12px 미만 글자를 검사합니다.
- **시각 회귀(기준 스크린샷 비교):** 기준 스크린샷을 저장해 두고 자동으로 비교하는 테스트는 **없습니다**. 대신 다음을 사람이 직접 보는 방식으로 확인했습니다.
  - 이상현상별 스크린샷 갤러리(`npm run e2e:gallery`)
  - README 스크린샷
- **플레이테스트:** 모든 엔딩 확인은 자동 플레이스루로 했습니다.
  - 자동화가 줄인 부분: 신고 현장까지 순간이동하고, 신고 사이 대기 시간을 건너뜁니다.
  - 실제 코드 경로 그대로인 부분: 현장 도착 판정, 상호작용(E 키), 보고 입력(태블릿 클릭), 엔딩 판정.
  - 사람이 실제 속도로 끝까지 플레이한 적은 **없습니다**. 그래서 30–45분 목표 플레이 시간도 측정하지 않았습니다.
- **브라우저 QA:** 헤드리스 Chrome(Windows, GPU 1종)에서만 했습니다. 다음은 확인하지 못했습니다.
  - 포인터 잠금(마우스 시점)
  - 전체화면 전환
  - 실제로 들어 본 소리의 품질
  - Firefox와 Safari

## 6. 최초 요청 이후 추가 요청으로 바뀐 것

| 요청 | 변경 |
| --- | --- |
| README에 게임 이미지 포함 | `docs/screenshots/` 10장, README 스크린샷 섹션, 촬영 스크립트 `tests/e2e/readme-shots.mjs` |
| 윈도우용 실행 파일 | `start.bat` (설치 → 빌드 → 실행, `rebuild`, `dev` 옵션) |
| Z-fighting 최적화 | 겹침 검사기(`npm run qa:zfight`)를 새로 만들었고, 다음을 수정했습니다: <br>• 벽 장식을 서로 다른 깊이로 배치 <br>• 중복 벽 제거 <br>• 문틀과 문짝 간격 조정 <br>• 정적 박스에 월드 좌표 UV 적용 <br>• 카메라 near 0.05 → 0.1 |
| 엘리베이터 겹침·문 닫혀도 운행이 보임 | 승강기 홀 벽을 승강로 앞으로 옮겼습니다. 승강장 문짝은 벽 속으로 들어가게 바꿨습니다. 이 과정에서 층 표시기 숫자가 틀 안에 묻혀 안 보이던 것도 고쳤습니다. |
| 액자 Z-fighting | 액자를 층위별로 다시 만들었습니다. 검사기의 놓침 버그(두께 0인 경계 상자)를 고쳐 다시 검사했고, 추가로 찾은 비상구 표지 겹침 등도 고쳤습니다. |

위 수정으로 바뀐 형태는 다음과 같습니다.

- 복도 벽 장식이 벽면보다 1.2–2.5 cm 앞으로 나왔습니다.
- 승강기 홀 벽의 위치가 15 cm 앞으로 옮겨졌습니다.
- 계단실 비상구 표지가 문 위 표지판보다 위로 올라갔습니다.
- 택배 탑은 11상자에서 9상자(바닥부터 천장까지)로 줄었습니다.
- 우편함 칸 사이에 1 cm 틈이 생겼습니다.

## 7. 진행 과정의 특이 사항

- 첫 세션은 대화 기록에 쌓인 이미지가 "many-image requests: 2000 pixels" 제한에 걸려 중단됐습니다. 새 세션에서 세션 기록(`messages.jsonl`)을 텍스트로만 추출해 이어서 진행했습니다. 이후에는 이미지를 1600px 이하로 줄이고, 필요한 최소량만 확인했습니다.
- 첫 세션 기록 파일은 현재 삭제되어 확인할 수 없습니다. 그래서 첫 세션에 한 결정의 세부 사유(예: 3번 항목의 이상현상 5개 제외 사유)는 이 문서에 적지 못했습니다.
